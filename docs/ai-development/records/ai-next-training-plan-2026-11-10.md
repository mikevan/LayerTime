# Next training cycle after the overnight experiments

Do not promote any tested language-model candidate to normal reporting. The custom adapter increased cited policy-group coverage, but introduced more unsupported invalid-clock warnings and did not transfer to the broader Timeline task. SmolLM3 also needs substantial interface and factual work. These results justify improving evidence contracts and training material before a larger run.

## Preserve facts before generating prose

Keep the existing Kotlin evidence/correlation engine responsible for observed counts, client/BSSID matching, timestamp validity, episode segmentation, spans, preceding-request delays and observed names. Exact spans/delays and cross-page name citations have already been added locally and tested; they were not deployed.

Have the model reference typed facts and episode IDs, with claims checked against those facts before a report is accepted. A group containing zero linked exchanges is not the same as a recording containing no exchanges. An invalid timestamp cannot support an elapsed-time claim. An observed request is not a confirmed disconnect, and an exchange is not completed authentication. Names and addresses remain observations, not ownership or physical attribution.

Use constrained schema generation to address fences, extra fields and malformed JSON, then evaluate factual correctness separately. A grammar cannot make a wrong direction or invented interval true. Keep urgent evidence summaries available without waiting for a generated explanation; measured desktop generation ranged into tens of seconds, and phone latency was not measured in this round.

## Train and route distinct skills

Treat burst-policy reporting, Timeline linkage, BLE feature interpretation and prompt-to-Builder authoring as distinct, explicit tasks. Evaluate each before sharing an adapter across them. Use typed, bounded tool interfaces for atoms and agents, with validated declarative workflows for execution. The existing flow engine remains useful for reproducible analytics; these experiments do not justify replacing it with unconstrained agent reasoning.

The shared prompt formatter now verifies message retention. Training and inference support explicit leading-system merging for models whose native templates accept one system message. Preserve this contract in each pluggable model adapter; Qwen and Smol should receive the same logical instructions through their supported native representations. This work does not require an Apple migration or a phone-vendor AI service.

## Expand reviewed material, not merely variants

The latest language adapter trained on 128 controlled variants from eight original synthetic families. It updated 2,949,120 LoRA parameters and saved an 11,815,504-byte patch requiring the separate frozen base. That is a bounded experiment, not dense wireless-domain qualification.

Available material for a future reviewed intake includes 24 source-backed NIST cards, 25 D3FEND teaching candidates, eight Builder proposals, 19 revised Timeline pages and six BLE reference-window candidates. Keep their purposes distinct: the Timeline versions reuse the same 14 scenarios; the BLE examples illustrate three questions using two recordings in one testbed. None of those candidate counts is a count of independent field environments. Current admission/approval flags must be respected rather than concatenating the folders into training.

Add licensed, independently recorded Wi-Fi identity/order cases and more diverse benign BLE recordings. Preserve whole recording/environment families across splits. Have relevant experts check protocol meaning and intended users check urgent wording. Retain raw evidence, source rights, units and label scope. The public BLE session labels describe recording conditions, not the maliciousness of every packet. InSecTT connection measurements cannot be pooled with advertisement-spam labels, and their timestamp units still need verification for rate-based tasks.

AWID access remains unresolved. The inspected KRACK/Kr00k CSV lacks required identity/exchange fields; unavailable or incompatible sources should remain excluded. Quarantined generic instruction sets contain factual errors and must not be used just to increase row counts. Use the already examined held-out scenarios as development diagnostics after making revisions; establish fresh held-out material before claiming improvement.

## Gate the next run and release

Before a longer job, investigate the nonfinite gradient-norm readings at steps 13 and 28, record loss-scaling/gradient diagnostics, and add resumable checkpoints with exact corpus/runtime/optimizer provenance. Final finite tensors and a no-skips ledger do not explain those readings. Current training saves a final adapter; it is not a tested restart/recovery system.

Repeat matched original/adapted/challenger tests with task-specific factual, coverage, format and readability criteria. Keep post-hoc diagnostics separate from prespecified measures. Require correct uncertainty, no invented outcomes, and acceptable behavior on linked, unlinked, broadcast, malformed and invalid-clock observations. Measure mobile memory and latency separately before any future release work.

Retain the CatBoost BLE pilot as experimental within its single-testbed scope. The anomaly ensemble's 99.48% normal-window false-flag fraction makes it unsuitable for issuing warnings. Do not combine its flags into a product verdict without new benign data and independent validation. No model or app deployment was performed during this overnight cycle.
